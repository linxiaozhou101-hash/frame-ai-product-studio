# 项目展示与面试讲述

[返回项目首页](../README.md) · [查看架构](ARCHITECTURE.md)

本页把仓库中已实现、已验证的内容整理为展示素材。简历中的动作和贡献范围应对应实际参与的部分。

## 一分钟介绍

FRAME 是一个用 Python 和 Streamlit 开发的商品图换背景应用，支持上传图片、选择三种场景、预览商品轮廓、真实生成以及下载结果。

项目最初直接调用整图编辑接口，希望提示词能约束模型保留商品。实际测试出现了背景变化不明显、商品却被改画的问题。因此改成先识别商品区域，用蒙版限定背景编辑，再将原商品像素合成回结果，并处理轮廓外的重影。

应用按异步任务处理提交、查询、下载和合成。查询或下载失败时，重试继续使用已有任务，并保留用户的图片与风格。目前通过 60 项自动化测试，也用同一张真实杯图验证了三种背景。它的重点是可检查的商品保留和可恢复的生成流程，当前仍是本地应用，复杂商品轮廓需要进一步验证。

## 两分钟演示顺序

1. **先看结果。** 打开首页对比图，指出三种背景变化与杯口、把手的保留情况。这是实际 API 输出加本地合成后的结果。
2. **展示真实操作。** 上传一张商品照片，选择风格，识别轮廓；说明杯把孔洞属于可编辑背景。
3. **展示生成过程。** 点击生成，指出状态、耗时和任务 ID；查看结果并下载 PNG。
4. **展示恢复能力。** 用已有测试说明断网和超时后的恢复逻辑，不需要在演示现场额外制造付费任务。
5. **说明边界。** 展示修正蒙版入口，解释透明材质、复杂轮廓和会话丢失仍是当前限制。

首次自动分割需要下载模型，现场演示前可以先完成一次轮廓识别。展示仓库样例不需要 API Key；现场生成需要本地配置并会按服务规则计费。

## 可以展开讲的三个技术问题

### 为什么提示词不够？

“保留商品”是一项语义要求，整图生成仍可能改变颜色、把手或文字。项目将问题拆开：模型负责生成新背景，本地算法负责确定哪些商品像素必须保留。二值编辑蒙版用于云端区域约束，软 alpha 用于本地合成，两者语义和用途不同。

这个方案也有代价：分割漏掉的部分不会得到完整保护，边缘融合和背景光照仍需检查。因此页面先展示商品轮廓，并提供人工蒙版入口。

### 如何避免失败重试重复生成？

`Job` 保存 `task_id`、结果 URL 和原始结果图片。失败发生在查询阶段时继续查原任务，失败发生在下载阶段时继续取原结果，本地合成失败时直接复用已下载的数据。只有任务明确终止或结果过期等情况，用户显式重试才会提交新任务。

首次提交超时且没有 ID 时仍存在不确定性：云端可能已经受理。代码不会自动重发 POST，并提示先检查调用记录。这一边界与“所有请求绝不重复”是不同的。

### 如何证明改动有效？

分别验证三个层面：

- **接口正确性：** 检查请求字段、异步头、Base64、响应状态与错误处理。
- **确定性逻辑：** 检查商品实心区域像素不变、杯把孔洞可替换、蒙版对齐以及原任务恢复。
- **真实效果：** 用此前效果不佳的杯子照片，分别生成三种背景并人工对比。

60 项测试的云端边界是模拟响应，不构成模型效果评测。真实验证只有同一张杯图的三种输出；该图片没有文字或 Logo，文字保留依据的是合成单元测试。不能据此宣称所有包装、材质与场景都已验证。

## 简历项目描述素材

**FRAME / AI Product Studio｜Python、Streamlit、图像处理、异步 API**

- 构建商品图换背景应用，接入阿里云百炼真实异步图像编辑接口，支持图片上传、三种场景、状态展示、并排对比与结果下载。
- 针对整图编辑中商品被重绘的问题，采用本地商品分割、背景蒙版局部重绘和原像素合成，并提供轮廓预览与人工蒙版入口。
- 实现按阶段恢复的生成流程，保留任务 ID、结果 URL 和下载数据，查询或下载失败时优先恢复原任务；使用 60 项自动化测试覆盖主要输入、接口与重试路径。

实际负责的部分可以进一步细化到模块和具体决策。不要将本地演示写成已服务大量用户、已完成线上部署或自研了生成模型。

## 常见追问

| 问题 | 与当前实现一致的回答 |
| --- | --- |
| 模型可以随便替换吗？ | 模型名由环境变量配置，但目前只适配 `wanx2.1-imageedit` 的蒙版协议。其他模型需实现独立请求与响应适配。 |
| 为什么保留原像素，还需要云端蒙版？ | 蒙版让模型在生成背景时参考商品位置与形状；本地合成进一步确保实心商品区域取自输入。两者分工不同。 |
| 识别失败怎么办？ | 不降级到整图重绘；保留输入并提示重试，或上传修正蒙版。 |
| 程序重启后能恢复任务吗？ | 目前不能自动恢复。任务在当前 Streamlit 会话中，后续可增加持久化记录和独立任务执行器。 |
| 是否适用于透明玻璃？ | 目前没有系统验证。透明、反光、细线和复杂背景可能需要更好的分割、去底色与融合方法。 |
| “像素差为 0”代表什么？ | 本次三个结果在 alpha 为 255 的商品区域，和尺寸适配后的输入逐通道相同；不代表背景自然度或轮廓完整性达到 100%。 |
| 下一步优先做什么？ | 扩充真实商品验证集、改善蒙版修正体验、持久化任务与结果，之后再考虑批处理和多模型。 |
